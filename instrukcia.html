Структура сайта

Сайт на PHP без базы данных и без сборщиков. Каждая страница — отдельный файл в корне, общие части лежат в inc/, данные — в data/.

Что заливать на сервер, а что нет

inc/, data/ЗаливатьБез них страницы не соберутся. Из браузера эти папки закрыты (.htaccess отвечает «не найдено»).

Выкладка на сервер

Хостинг — Apache с PHP (нужен PHP 7.4 или новее с модулями mbstring и gd). Заливать можно через FTP/SFTP-клиент (FileZilla, Transmit, Cyberduck) или панель хостинга.

Первая выкладка или полная перезаливка

  1. Сделайте копию того, что сейчас на сервере (скачайте папку сайта или сделайте резервную копию в панели хостинга).

  2. Залейте в корень сайта всё из столбца «Заливать» таблицы выше, сохраняя папки.

  3. Проверьте, что .htaccess попал на сервер: некоторые FTP-клиенты по умолчанию скрывают файлы, начинающиеся с точки.

  4. Пройдите проверку.

Стили и скрипты подключаются с меткой версии (?v=… по дате файла), поэтому после заливки гости сразу получают новые версии. Картинки кэшируются на месяц, поэтому у каждого нового меню новое имя файлов.

Обновление меню (раз в два месяца)

Всё делается на своём компьютере (Mac) в папке сайта, потом результат заливается на сервер.

Один раз подготовить компьютер

brew install poppler

Это программы pdftoppm и pdfinfo: они рисуют страницы PDF картинками. Ещё нужен PHP с GD и WebP (в Laravel Herd уже есть).

Каждое новое меню

  1. Получите PDF из типографии и придумайте новое имя файлов: латиница, цифры, «_» и «-». Имя должно отличаться от прошлого, например menu_restaurant_fabrikant2026_zima.

  2. Запустите в Терминале из папки сайта:

    cd ~/Herd/fabrikant
php tools/new-menu.php ~/Downloads/новое-меню.pdf menu_restaurant_fabrikant2026_zima "Зима 2026"

    Скрипт сам сделает всё за 1–2 минуты:

    • скопирует PDF в uploads/;
    • нарисует страницы картинками в assets/img/menu/ (1600 px, лёгкие 1000 px, миниатюры 200 px);
    • сделает лёгкий PDF uploads/{имя}-web.pdf и страницы 3200 px для увеличения;
    • перепишет data/menu.php: имя, сезон, подписи страниц. Если страниц столько же, сколько в прошлом меню, подписи страниц и разметка разделов переносятся из прошлого.

  3. Проверьте подписи страниц в data/menu.php, массив 'pages': по строке на страницу, коротко и словами гостя («Горячее и гриль»). Это подписи в содержании газеты и описание страниц для незрячих.

  4. Проверьте разметку разделов в окне (подробно — ниже):

    php tools/menu-sections.php

  5. Откройте меню локально: http://fabrikant.test/menu.php. Пролистайте на ПК и в узком окне, как на телефоне.

  6. Залейте на сервер новые файлы:

    data/menu.php
uploads/{новое имя}-web.pdf
assets/img/menu/{новое имя}-*     ← все файлы нового меню (около 40 шт.)

  7. Удалите старые файлы — после проверки на сайте. Команду для своего компьютера напечатает new-menu.php в конце. На сервере удалите те же файлы со старым именем в uploads/ и assets/img/menu/.

Нельзя заливать новое меню под старым именем файлов: у гостей картинки держатся в кэше до месяца, и они увидят старые цены.

Разметка разделов

Из разметки сайт делает кадры разделов на телефоне (крупно, без увеличения), кнопки разделов и ссылки вида /menu.php#supy, которые подходят для QR-кодов и рекламы.

  1. Запустите php tools/menu-sections.php. Окно откроется в браузере само; если нет, откройте ссылку, которую напечатал Терминал.

  2. Слева выберите страницу. Рамки разделов прошлого меню уже стоят на своих местах.

  3. Съехала рамка — потяните её мышью или за синие углы. Новый раздел — обведите мышью от заголовка до последней цены и впишите название, как на кнопке («Супы»). Раздел перешёл в соседнюю колонку — у раздела нажмите «+ рамка» и обведите продолжение.

  4. Порядок в списке справа — порядок на телефоне (кнопки ↑ ↓). Лишняя рамка удаляется кнопкой «Удалить» или клавишей Delete.

  5. Нажмите «Сохранить в data/menu.php», затем остановите окно в Терминале: Ctrl+C.

Если вёрстка меню не поменялась, проверка занимает около минуты, разметка с нуля — 10–15 минут.

Если разделы не размечены, сайт показывает меню целыми страницами, ничего не ломается.

Адрес раздела строится из названия: «Супы» → #supy. Если QR-код уже напечатан со ссылкой на раздел, не переименовывайте этот раздел.

Акции и плашка «Сейчас действует»

Все акции записаны в data/promos.php. Из этого файла их берёт страница «Акции», а на странице меню под шапкой плашка сама показывает, что идёт по времени Симферополя:

  • в будни с 12:00 до 15:00 — «Сейчас, до 15:00 · Счастливые часы · −25% на меню кухни»;
  • в среду — «Сегодня весь день · Мужские дни · −50% на пиво собственной пивоварни»; в среду с 12 до 15 видны обе акции;
  • до начала акции — «Сегодня с 12:00…»; если сегодня ничего нет — ближайшая: «Завтра с 12:00…», «В среду…».

Открытая страница пересчитывает плашку раз в минуту, поэтому в 12:00 и 15:00 она меняется сама. Нажатие на плашку ведёт к карточке акции на странице «Акции».

Как поменять расписание

'when' => array('days' => array(1, 2, 3, 4, 5), 'from' => '12:00', 'to' => '15:00', 'not_holidays' => true),
  • days — дни недели: 1 — понедельник, 2 — вторник … 7 — воскресенье;
  • from, to — часы; если их нет, акция идёт весь день;
  • not_holidays — акция не идёт в праздники ('holidays') и в дни из 'no_dates';
  • short — короткий текст для плашки, например «−25% на меню кухни»;
  • 'off' => true — временно выключить акцию везде, не удаляя её.

Если у акции нет when (например, «Имениннику»), в плашке она не появляется, но на странице «Акции» остаётся.

Концерт или перенос выходных

Впишите дату в 'no_dates' в конце data/promos.php и залейте файл на сервер — в этот день счастливые часы не покажутся:

'no_dates' => array(
    '2026-11-14',   // концерт
),

Дни недели и часы сайт берёт по времени Симферополя, а не по часам на компьютере гостя.

Git

Сайт под git: публичный репозиторий github.com/itwawox/fabrikant-site. Каждое изменение (новое меню, правка акций) — коммит; откатиться можно на любой прошлый.

git status                         # что поменялось
git add -A
git commit -m "Меню: зима 2026"
git push                           # отправить на GitHub

В репозиторий не попадают (файл .gitignore): PDF меню в uploads/ (их делает new-menu.php), видео главной, docs/private/ с доступами к хостингу, файлы редактора. Репозиторий публичный — пароли и доступы в код не записывать.

Git хранит код; на хостинг сайт по-прежнему заливается вручную, по списку из раздела «Выкладка».

Проверка после выкладки

  • Главная, «О ресторане», «Галерея», «Акции», «Контакты» открываются без ошибок.
  • /menu.php на ПК: слева разделы, справа страницы, под курсором лупа. Кнопка «Листать газету» открывает 3D-газету.
  • /menu.php на телефоне: сверху полоса разделов, кадры читаются без увеличения, внизу кнопка «Забронировать стол».
  • Касание страницы или кадра открывает увеличение в этом месте, текст чёткий.
  • Под шапкой меню видна плашка акций; в будни с 12 до 15 — «Сейчас, до 15:00 · Счастливые часы». На странице «Акции» та же плашка над карточками.
  • «Скачать PDF» скачивает файл около 4 МБ с именем «Меню ФабрикантЪ, …pdf».
  • Ссылка /menu.php#supy открывает меню сразу на супах.
  • /data/menu.php, /inc/_menu.php и /tools/new-menu.php отвечают «страница не найдена».
  • /instrukcia.html и /audit.html на сервере не открываются (их там нет).
