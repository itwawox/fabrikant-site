## 1. Цель

Сейчас сайт — PHP-файлы без базы и без админки: меню, акции, галерея, тексты правятся в коде, новое меню
выкладывается командой в терминале. Нужно перенести сайт на Laravel так, чтобы:

1. **Всё настраивалось из админки** — тексты страниц, контакты, акции, галерея, SEO, меню.
2. **Меню обновлялось загрузкой одного PDF**: владелец загружает файл из типографии, сайт сам делает картинки
   страниц, лёгкий PDF, миниатюры, копии для увеличения, переносит разметку разделов, показывает превью — и по кнопке
   (или по дате) публикует. Меню меняется **раз в два месяца**, поэтому процесс должен занимать минуты и не требовать
   знаний.
3. **Гость не заметил переезда**: дизайн, скорость, адреса, ссылки из QR-кодов (`/menu.php#supy`) работают как раньше.

Подробная схема папок и процессов — в `instrukcia.html` в корне; UX-аудит меню — `audit.html`.

Данные и логика, которые становятся моделями и сервисами:

- `data/menu.php` — текущее меню: `name`, `season`, `pages` (подписи страниц), `sections` (разделы: страница,
  название, рамки `[x, y, w, h]` в долях листа, у раздела может быть несколько рамок).
- `inc/_menu.php` — `menu_slug()` (транслитерация в адрес раздела), `menu_sections()` (проверка и порядок).
- `tools/new-menu.php`, `tools/build-menu-web.php`, `tools/build-menu-thumbs.php` — конвейер PDF → картинки.
  Параметры подобраны вручную, **сохранить**: страницы 1600 px JPEG q85 → WebP q82 (1600 и 1000 px),
  миниатюры 200 px WebP q55, копии для увеличения 3200 px WebP q70 (из PNG pdftoppm), лёгкий PDF —
  JPEG 1800 px q65, собранный в PDF без перекодирования (DCTDecode), размер листа как у исходника (A3).
- `tools/menu-sections.php` — окно разметки разделов (рамки мышью, «+ рамка», порядок, сохранение).
- `data/promos.php` + `inc/_promos.php` + `assets/js/promos-now.js` — акции с расписанием
  (`days` 1–7, `from`/`to`, `not_holidays`), праздники (`holidays` месяц-день), дни без акций (`no_dates`),
  часовой пояс `Europe/Simferopol`. Логика PHP и JS совпадает (проверено на 1344 точках) — сохранить это свойство.
- `data/gallery.php` + `data/gallery.build.php` + `tools/build-images.php` — рубрики, 10 фото, варианты
  AVIF/WebP/JPG шириной 480/720/исходная, хэш рецепта в имени файла.
- Тесты: `node --test tools/tests/` (57 шт.: маршруты, пружина, изгиб листа, прогресс, увеличение, акции) — перенести.

Особенности, которые легко сломать (подробнее в памяти проекта и комментариях кода):

- CSS `press.css` и `book.css` используют **cascade layers**: правило в раннем слое проигрывает позднему независимо
  от специфичности; unlayered-правила из `site.css` сильнее всех слоёв (отсюда «щит» `all: revert-layer`).
- `html` имеет `scroll-behavior: smooth` → `scrollIntoView({behavior:'auto'})` плавный; нужен `'instant'`.
- Chrome качает `loading="lazy"` картинки даже в `display:none` → скрытые картинки через пустой `src` + `data-src`
  или `<source media>` с прозрачной точкой.
- three.js лежит локально (`assets/vendor/three/0.185.1/`), подключается import-map'ом с SRI.
- Метрика: счётчик 26918373, цели `menu_pdf`, `menu_call`, `menu_zoom`, `menu_toc`, `menu_section`,
  `menu_mode_flat`, `menu_mode_book`.
- Комментарии в коде — по-русски, простым языком, объясняют «почему». Сохранить этот стиль.

## 4. Публичная часть

### 4.1 Адреса

| Новый адрес | Старый | Правило |
|---|---|---|
| `/` | `/index.php` | 301 со старого |
| `/menu` | `/menu.php` | 301, **фрагмент `#…` браузер сохраняет** — ссылки `/menu.php#supy`, `#page-3` должны работать |
| `/about` | `/about.php` | 301 |
| `/gallery` | `/gallery.php` | 301, фрагменты `#foto-…` сохраняются |
| `/promos` | `/calendar.php` | 301, фрагменты `#happyhours` и т. п. |
| `/contacts` | `/contacts.php` | 301 |

Адреса разделов меню (`#supy`) и фото (`#foto-fasad`) **не меняются** при переезде и при обновлении меню, пока
название раздела то же. В админке у раздела показывать его адрес и предупреждать при переименовании раздела,
на который могли напечатать QR («адрес раздела изменится: было #supy, станет #supy-i-bulony»). Дать возможность
закрепить адрес вручную (поле `slug`, по умолчанию из названия).

### 4.2 Перенос вёрстки

- Каждую страницу перенести в Blade **один в один по HTML**: классы, атрибуты, порядок, комментарии.
  `inc/_head.php`, `_navbar.php`, `_footer.php` → layout и компоненты.
- CSS/JS из `assets/` → `resources/` (через Vite с версиями) или `public/assets/` (как есть) — выбрать одно,
  обосновать. Модули `menu3d/` и `gallery/` подключаются через import-map — сохранить механизм `module_tags()`.
- Критерий: **визуальное сравнение** старой и новой страницы на 390 px, 768 px, 1209 px, 1440 px — без отличий
  (скриншоты в `docs/visual/`). Lighthouse не хуже исходника (LCP, CLS).

### 4.3 Страница меню

Вся текущая функциональность (вид для чтения, кадры разделов, полоса разделов, лупа, газета 3D, увеличение в точке
нажатия, плашка акций, кнопка брони на телефоне, адреса разделов, цели Метрики) — данные берутся из опубликованного
меню в БД вместо `data/menu.php`. Если у меню нет разметки разделов — страницы целиком (как сейчас).

Добавить (этап 3 из аудита, по возможности в этом проекте):
- **Поиск по блюдам**: при обработке PDF распознавать текст (Tesseract `rus`), хранить строки с координатами;
  поиск подсвечивает строку на картинке. Включается в настройках; без Tesseract — поиска нет, остальное работает.
- Текст распознанного меню — скрытой версией для экранного диктора и для поисковиков (без показа зрячим).

## 5. Админка (Filament 4)

Адрес `/admin`, вход по e-mail и паролю, 2FA по желанию. Интерфейс на русском. Всё — с журналом изменений.

### 5.1 Меню — главный модуль

**Список меню** (сезоны): название («Осень 2026»), статус (`черновик` / `обработка` / `готово` / `опубликовано` /
`архив`), страниц, разделов, дата публикации, кто загрузил.

**Создание меню**:
1. Форма: сезон (текст), PDF (до 100 МБ, только PDF), «перенести подписи и разделы из текущего меню» (по умолчанию да,
   если число страниц совпадает), дата публикации (необязательно).
2. После загрузки — **задача в очереди** с прогрессом в админке (страница N из M, этап):
   - проверка PDF (`pdfinfo`: страницы, размер листа; не битый);
   - для каждой страницы: JPEG 1600 → WebP 1600 и 1000, миниатюра 200, копия 3200 (параметры раздела 2);
   - лёгкий PDF (≈4 МБ) для кнопки «Скачать»;
   - распознавание текста (если включено);
   - перенос подписей страниц и разделов из текущего меню при совпадении числа страниц;
   - имена файлов уникальны для каждого меню (кэш браузера — месяц): `menus/{id}-{hash}/{n}-1600.webp` и т. п.
3. Ошибки — человеческим языком («PDF защищён паролем», «нет программы pdftoppm на сервере — сообщите разработчику»),
   с кнопкой «повторить».

**Карточка меню**:
- подписи страниц (по строке на страницу, подсказка «коротко и словами гостя»);
- **редактор разделов** — перенос `tools/menu-sections.php` в кастомную страницу Filament (Livewire + Alpine):
  страницы слева, лист с рамками, рисование мышью, перетаскивание и углы, «+ рамка» для раздела в двух колонках,
  порядок (drag-n-drop), название, адрес раздела, удаление, предпросмотр кадра «как на телефоне»;
  кнопка «скопировать разметку из прошлого меню»; подсветка рамок, вылезающих за текст (необязательно);
- **предпросмотр** меню целиком (ПК и телефон) по секретной ссылке до публикации;
- кнопки: «Опубликовать сейчас», «Запланировать», «Снять с публикации», «Откатить на прошлое меню».
- исходный PDF типографии хранится, но гостям не отдаётся.

Опубликовано всегда ровно одно меню. Архивные можно удалить (с файлами) — с подтверждением.

### 5.2 Акции

CRUD: название, скидка, «на что», короткий текст для плашки, фото (с обработкой как сейчас — монохром делает CSS),
описание для незрячих, строки «Когда/Часы», условия (повторитель), порядок, включено/выключено.
**Расписание**: дни недели (чекбоксы), часы с/до или «весь день», «не действует в праздники», период действия
акции (с/по, необязательно). Без расписания — акция только на странице «Акции».

Отдельно: **праздники** (месяц-день, предзаполнить официальными РФ) и **дни без акций** (дата + причина: концерт,
перенос). Виджет «Что гость видит сейчас» + **симулятор**: выбрать дату и время → показать плашку.
Логика расписания — один сервис PHP + JS с общими тестами (как сейчас, паритет обязателен).

### 5.3 Галерея

Рубрики (название, подпись, порядок), фото (загрузка, рубрика, место в сетке lead/std/tall, подпись, alt, порядок
drag-n-drop, адрес `#foto-…`). Варианты AVIF/WebP/JPG 480/720/исходная — в очереди, рецепт как в
`tools/build-images.php`. Удаление старых вариантов автоматически.

### 5.4 Страницы и тексты

Тексты «О ресторане» (рубрики, вакансия), «Контакты», главной (заголовок, видео — загрузка с подсказкой по размеру;
сжатие ffmpeg в очереди, если есть на сервере), 404. Где вёрстка сложная — поля под конкретные блоки, а не
WYSIWYG на всю страницу (чтобы владелец не сломал газетную вёрстку). SEO каждой страницы: title, description,
OG-картинка.

### 5.5 Настройки сайта

Название, телефон(ы), адрес, часы работы, координаты для карты, соцсети, Яндекс.Метрика (ID и вкл/выкл),
каналы брони (телефон, Telegram, WhatsApp, форма), данные для schema.org (Restaurant/Menu), robots,
ресторан в Ялте (сейчас в меню есть ссылка). Всё, что сейчас захардкожено в PHP, — сюда.

### 5.6 Брони (если включена форма)

Форма на сайте (дата, время, гостей, имя, телефон, комментарий, согласие на обработку ПДн) → заявка в админке со
статусами + уведомление в Telegram-бот ресторана. Антиспам (honeypot + rate limit). Хранение ПДн — по 152-ФЗ
(срок, удаление), отразить в политике.

### 5.7 Пользователи, роли, журнал

Роли: **владелец** (всё), **менеджер** (меню, акции, галерея, брони), **SMM** (галерея, тексты). Журнал действий
с фильтрами. Сброс пароля по почте.

### 5.8 Дашборд

Текущее меню (сезон, дата публикации, «обновлено N дней назад», напоминание через 60 дней), акции сегодня,
последние брони, статус очереди и последних задач обработки, место на диске, дата последнего бэкапа.

## 7. Сервисы и очереди

- `MenuPdfProcessor` (job-цепочка: Inspect → RenderPages → BuildWebPdf → Ocr → CarryOver → MarkReady) —
  каждый шаг отдельной задачей, прогресс в БД, повтор с места падения.
- `MenuPublisher` — публикация/откат, сброс кэша страницы меню.
- `PromoSchedule` — расчёт «что сейчас» (PHP) + `resources/js/promos-now.js` (JS), общий набор тестовых случаев
  в JSON, по которому гоняются и Pest, и `node --test`.
- `ImageVariants` — варианты для галереи и акций.
- Расписание (`schedule:run` из cron): публикация запланированных меню, чистка временных файлов, бэкап, напоминание
  «меню старше 60 дней».
- Страницы сайта кэшируются целиком (response cache) и сбрасываются при изменениях в админке.

## 8. Нефункциональные требования

- **Скорость**: не хуже текущего сайта. Первый экран меню на телефоне — одна картинка-кадр; размеры картинок как сейчас.
- **Доступность**: alt у страниц меню, заголовки разделов, фокус, `prefers-reduced-motion`; админка — клавиатурой.
- **Безопасность**: CSRF, политики доступа на каждое действие, проверка MIME загрузок, лимиты размеров,
  обработка PDF в отдельном процессе с таймаутом, запрет выполнения в `storage`, секреты только в `.env`.
- **SEO**: 301 со старых адресов, `sitemap.xml`, canonical, OG, schema.org Restaurant + Menu (`hasMenu`).
- **Надёжность**: ежедневный бэкап БД и `storage` (хранить 14 дней), инструкция восстановления.
- **Логи**: ошибки обработки меню видны в админке и в `storage/logs`.

## 10. Хостинг и выкладка

Сайт на виртуальном хостинге **reg.ru**, сервер `vip277.hosting.reg.ru` (31.31.197.20, nginx перед Apache),
аккаунт и пути — в `docs/private/hosting.md` (этого файла нет в публичном репозитории: он в `.gitignore`,
попросите у владельца).
На этом же аккаунте уже работает Laravel-проект (`car-on-time-dev`) с планировщиком в cron — схема проверена.

**Проверено 4 октября 2026:**

| Что | Есть | Вывод |
|---|---|---|
| PHP | 8.3.31 и 8.4.25 (`/opt/php/8.4/bin/php`) | Laravel 12 — на 8.4 |
| Расширения | gd, imagick, intl, mbstring, pdo_mysql, zip, fileinfo, exif | Всё нужное |
| WebP через GD | да | Конвейер меню как есть |
| AVIF через GD | **нет** | AVIF для галереи — через Imagick, если его ImageMagick умеет AVIF (проверить), иначе только WebP/JPG |
| MySQL | Percona 5.7 | Laravel 12 поддерживает 5.7; без функций MySQL 8 (JSON-индексы, CTE в миграциях не использовать) |
| cron | да | Планировщик и очередь: `* * * * * /opt/php/8.4/bin/php …/artisan schedule:run`; очередь — `queue:work --stop-when-empty --max-time=50` из планировщика (supervisor нет) |
| git, node | да | Деплой через `git pull`; сборку Vite делать локально и коммитить `public/build` или собирать на сервере node'ом |
| composer | **нет в PATH** | Положить `composer.phar` в аккаунт и звать `/opt/php/8.4/bin/php composer.phar` |
| poppler (`pdftoppm`, `pdfinfo`) | **нет** | Рисовать PDF через **Ghostscript** (`/usr/bin/gs` есть) — см. ниже |
| Ghostscript | да, `/usr/bin/gs` | Замена poppler |
| Tesseract | **нет** | Поиск по меню (этап 8): распознавать локально/внешним сервисом или отложить |
| ffmpeg | **нет** | Сжатие видео главной — только локально, в админке просто загрузка готового файла |
| Диск | общий раздел 1,8 ТБ, свободно 396 ГБ; квоту аккаунта уточнить в панели | Меню ≈ 60 МБ на сезон с исходником — хранить 3–4 последних |

**PDF без poppler.** В `MenuPdfProcessor` сделать драйвер рендеринга с двумя реализациями:
`GhostscriptRenderer` (по умолчанию на проде) и `PopplerRenderer` (локально, где он есть), выбор в настройках.
- число страниц и размер листа: `gs -q -dNODISPLAY -dNOSAFER -c "(file.pdf) (r) file runpdfbegin pdfpagecount = quit"`
  или Imagick `pingImage()`; размер листа — из `/MediaBox` (через gs или Imagick);
- страница в PNG нужной ширины: `gs -dSAFER -dBATCH -dNOPAUSE -sDEVICE=png16m -r<dpi> -dFirstPage=N -dLastPage=N
  -dTextAlphaBits=4 -dGraphicsAlphaBits=4 -o out.png file.pdf`, где dpi = ширина_px / ширина_листа_дюймы;
- дальше как сейчас: GD → JPEG/WebP нужных размеров, лёгкий PDF собирается из JPEG своим кодом (уже работает в
  `tools/build-menu-web.php`, poppler там не нужен);
- **сравнить качество** gs и poppler на осеннем меню 2026 (мелкий шрифт цен) — скриншоты в `docs/visual/`;
- PDF типографии весит ~40 МБ: проверить `upload_max_filesize`/`post_max_size` в настройках PHP хостинга
  (панель reg.ru → PHP) и лимит nginx; при нехватке — загрузка по частям (Filament/Livewire chunked upload);
- обработка восьми страниц должна укладываться в лимиты времени: каждая страница — отдельная задача очереди.

**Ещё проверить на этапе 0:** `upload_max_filesize`, `post_max_size`, `memory_limit`, `max_execution_time` для
PHP 8.4; `/opt/php/8.4/bin/php -r 'print_r(Imagick::queryFormats());'` (PDF, WEBP, AVIF) и политика ImageMagick
для PDF; можно ли направить корень домена на `public/` в панели reg.ru (у `car-on-time-dev` — посмотреть, как
сделано); квоту диска аккаунта.

Выкладка: `git pull` → `php composer.phar install --no-dev -o` → `php artisan migrate --force` → `php artisan optimize`
(очередь перезапустится сама — она запускается из планировщика каждую минуту). Описать в `docs/deploy.md` + скрипт
`deploy.sh`. Все команды на сервере — через `/opt/php/8.4/bin/php`, системный `php` может быть другой версии.
